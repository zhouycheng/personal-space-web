# 网站开场

所有首次直访（首页、作品、画布、OS、日记）先显示服务器输出的云雾准备页。同一个底部文字位置按实际任务显示「正在加载场景」「正在布置小岛」「正在准备海面与材质」「正在预热光影」「正在准备首帧」，就绪后替换为「点击拨开云雾」。点击或 Enter / Space 启动揭幕，连续云体从中心向四周退散，先露出完整远景海岛。首页相机沿弧线下降、靠近、转正，精确落在现有响应式总览位置。深链接在同一条时间线上逐渐混合远景轨迹与既有目标物轨迹，直接靠近日记、电脑、iPad 或文件木箱，不在总览位置停顿后另起一段动画。

## 职责

- `src/justin-kit/components/cloud-entrance/`：云雾、文字、悬停、插槽和输入过滤。可独立使用，未导入 Three.js 或本站数据；个人信息只改插槽与组件。
- `src/app/entranceRuntime.ts`：准备/就绪/揭幕/错误的协调、异步代次、点击锁和成功记录。
- `src/app/studioAppRuntime.ts`：组装场景、目标内容预加载、异常恢复及原地址续接。
- `src/contracts/studioPorts.ts`：`prepareStartup()` 和 `playEntrance()` 只返回 `OperationResult` 并报告进度，不暴露相机或 renderer。
- `src/contracts/startup.ts`：准备阶段及阶段完成进度；应用层负责文案，云雾组件不导入业务类型。
- `src/presentation/scene/studio/prepareSceneGeometry.ts`：单个 Worker 与主线程回退；共享生成函数产出植被、LOD、岩石和海岸几何，传输时共享属性缓冲只转移一次。
- `src/animation/studio/entranceMotion.ts`：时长 3000ms、真实向下俯角 60°、相对总览右偏 55°、取景占比 .3。`islandFraming.ts` 共用树冠、岛岸、码头和船的边界；普通浏览取景计算保持原结果。

## 就绪与时间

先给 SSR 准备页一次绘制，再导入场景。进度按模块加载、场景构造、必要纹理、着色器预热、有效绘制五步推进；不是下载字节百分比或计时增长。进入耗时阶段前提供绘制机会。Worker 生成环境几何与主线程家具装配并行；Worker 不可用、失败或超过 30 秒前台活动时间时，回退到相同生成函数并在步骤间让出绘制。取消、路由替换和卸载会终止旧 Worker。

海水法线图片最多等待 15 秒前台活动时间；隐藏页面与 BFCache 不消耗此期限。失败或超时使用既有解析波浪，迟到图片仅对尚存活的场景生效。光照配置后上传纹理并 `compileAsync()`，在开场起点和最终位置实际绘制验证。目标画布代码和专用 CSS 按需加载并等待样式就绪；React 共享运行时单独分包，首页不预取 `@xyflow` 编辑器。桌面已由外壳挂载，日记控制与清单已组装，书页与桌面文档仍按需加载。

等待点击时，海岛停在已绘制起点，暂停动态绘制。相机使用现有 `createActiveMotion`，云雾接收同一进度；隐藏页面暂停，恢复继续。resize 保留临时进度并重新计算起终点；落定后移除临时姿态、同步普通相机当前/目标值并清零速度。交互入口在落定前保持 inert，准备组件在结束后释放 Canvas、监听器与 RAF。减少动态效果保留准备与点击，以 240ms 淡出接到最终位置。

准备页底色、雾面、揭幕云体和文字由宿主注入与天空相同的环境快照，按真实时间、观测经纬度和太阳高度连续变化。同步 head 脚本在场景模块加载前应用同源配色，避免首屏闪出固定白昼底色。刷新遮罩与首次入口共用颜色，等待期间复用一秒时钟，配色实际变化才重绘。加载页和场景页面均不显示天色设置按钮。

场景从未激活状态构造，先预热再绘制，避免暂停动作在预热前额外提交完整绘制。云雾由 Canvas 连续密度场绘制，没有云图片下载和解码等待。三层横向舒展的云纱由多尺度平滑噪声和坐标扭曲生成，按不同速度漂移，以光学厚度表现透明度，中央逐渐变薄并向外围散开；准备页共用零进度采样，揭幕不使用残影合成。云色随观测点的天色变化，夜间降低蓝灰云层与散射高光，晨光偏淡暖，落日偏金黄。准备页 `data-timings` 记录五个真实步骤及就绪累计耗时；场景 `data-startup-timings` 记录纹理等待、上传、着色器预热和验证绘制耗时，便于检查加载停留，不参与进度增长。

## 路由与恢复

开场不修改请求地址或创建首页历史记录（仍保留既有 `/` → `/home` 规范化）。初始内容隐藏且不可交互，首页场景保持可测量；落定后按原 URL 的 query、slug、hash 进入内容。准备或揭幕期间 popstate 会取消旧任务，并为最新地址重新准备；旧回调不能更新组件。

只有首次揭幕成功落定才写 `sessionStorage['justin-entrance-completed']='1'`。已完成标签页刷新时仍显示同一云雾页，底部复用相同阶段文案并按真实准备进度从左向右填色；准备完成后云雾与文字自动淡出，不等待点击，也不启动相机开场动画。刷新保留当前路由。站内返回、后退/前进、BFCache 不重播开场或刷新遮罩。恢复旧标签页可能保留会话标记。存储拒绝时仅保留当前文档内成功状态，下次完整刷新可能重播。

错误状态提供组件内重试并复用场景恢复逻辑。错误内容出口使用 `?entrance=skip`，允许访问作品、画布、OS；该明确退出路径不会写入开场成功标记。普通入口不需要此参数。

## 验证入口

`data-timings` 同时记录导航至准备/就绪、云雾 CPU 与各阶段累计时间。`data-startup-timings` 区分模块等待、Worker 总时间、各生成函数 CPU、家具与后续装配 CPU、纹理等待/上传、编译和试绘。Worker 与家具时间有重叠，不能直接相加；`data-normals-wait` 标识资源就绪或超时。

几何合批保留索引、属性和三角形顺序；LOD 缓存网格拓扑与重心权重，不改变轮廓和误差阈值。海水只在贡献确定为零时跳过波浪频段或泡沫计算，屏幕导数与纹理采样保留在这些条件分支之前。远海天空混合维持原算法；提前分支在参考设备上的独立采样未显示稳定收益。阴影分辨率、风动更新、DPR 上限及相机交互参数保持原配置。

`tests/startup-geometry.test.mjs` 检查原算法 LOD 结果、索引合并和共享缓冲传输；`tests/e2e/startup-preparation.spec.ts` 检查阶段可见性、网络分包、Worker 回退、纹理超时和准备期导航。`scripts/startup-performance-measure.mjs` 通过 `PERF_URL`、`PERF_LABEL` 对已有生产服务采样三轮，将原始数据和截图写到 `.workspace/startup-optimization/`。测量期间不要同时运行另一浏览器检查或构建。

`tests/entrance.test.mjs` 验证真实俯角、精确落点、既有取景和存储降级；`tests/e2e/entrance*.spec.ts` 验证真实资源等待、文字互斥、首访/刷新/深链接、悬停、键盘、独立插槽、resize、后台恢复及 WebGL 错误。其他 E2E 通过 `helpers/app.ts` 使用已完成开场的标签页，继续覆盖正常场景和内容回归。图像、独立 HTML 预览和测量记录保留在 `.workspace/entrance-validation/`。

客户端预热旨在降低首次显露的停顿；不采用服务端 3D 预渲染或静态海岛替换，不承诺持续 FPS 提升。测量需使用相同浏览器、设备、光照、DPR、视口，三次重复，单独记录首次绘制、可点击时间、点击到落定和帧间隔。无头软件 WebGL 不能用来宣称设备性能。
