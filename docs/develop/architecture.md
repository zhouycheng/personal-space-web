# JustinSpace 架构与目录

Astro 负责路由与服务端渲染，React 负责画布，Three.js 负责工作室和日记实体书。稳定页面状态由 URL 决定；访客侧临时状态由每次挂载创建的 Nano Stores 与组件内状态持有。

## 目录职责

| 目录 | 责任 | 依赖方向 |
| --- | --- | --- |
| `src/pages/` | `/home`、`/works`、`/canvas`、`/os`、`/journal` 和 API 入口 | 装配其他层，入口保持薄 |
| `src/app/` | 路由、History API、依赖装配及页面生命周期 | 可组合内部层 |
| `src/contracts/` | 内容模型、`StudioIntent`、`ScenePort`、`TransitionPort` | 只依赖本层；不含 DOM、ReactFlow、Three.js |
| `src/content/` | 简历、作品、文件顺序、画布发布内容、日记和站点素材 | 可引用纯契约；真实个人内容另受 [CONTENT-LICENSE.md](../../legal/CONTENT-LICENSE.md) 约束 |
| `src/config/` | 场景配色、光照和书本外观 | 纯配置 |
| `src/data/repositories/` | 发布内容读取入口 | 内容与契约 |
| `src/data/selectors/` | 文件盒、作品列表、画布结构、实体书页等纯派生数据 | 输入参数、契约与配置；不读取 repository |
| `src/data/stores/` | 按页面实例创建的客户端状态、活动快照 | selector 与契约；访客状态不存服务端全局变量 |
| `src/application/` | 用户意图到导航/场景命令、日记阅读规则和活动状态规则 | 契约与数据；不依赖展示实现 |
| `src/presentation/scene/` | 3D 物件、灯光、渲染、GPU 资源释放 | 契约、配置和动画函数；文件资料由装配层注入 |
| `src/presentation/interaction/` | Three.js 拾取、画布几何与手势规则 | 交互计算；不决定业务路由 |
| `src/presentation/ui/` | Astro/React 页面、HTML 入口、组件、浏览器运行时和样式 | 向内层读取投影并发出意图 |
| `src/animation/` | 相机、书本和页面投影过场 | 契约与参数；不决定 URL |
| `src/infrastructure/client/` | 浏览器存储适配 | 仅持久化明确允许的字段 |
| `src/infrastructure/server/` | 日记清单与活动 SSE 等服务端适配 | 契约和数据 |
| `src/justin-kit/` | 可复用的桌面、窗口、背景、活动订阅源与采集 CLI | 不导入本站业务层 |

`src/content.config.ts` 和 `src/env.d.ts` 留在 Astro 约定的位置。`public/os-desktop/` 是桌面文件内容的唯一来源。`games/` 当前保留扩展说明，`src/content/games.json` 是空登记清单，尚无游戏运行时。

## 主要调用链

1. `src/content/site/*.json` → `src/data/repositories/site.ts` → `src/data/selectors/studioFiles.ts` → 工作室文件木箱、文件阅读视图和作品页。更换内容模型时修改 repository 适配和契约；展示组件消费同一组文件数据。
2. Three.js 物件与可访问的 HTML 入口都发出 `StudioIntent`。`src/application/studio/resolveIntent.ts` 决定导航或场景操作；`src/app/navigation.ts` 决定 URL 和历史；`src/animation/` 与 `ScenePort` 执行可取消过场。每次导航开始即更新 URL，过场使用 token 拒绝旧完成回调。
3. `src/content/canvas/published.ts` → canvas repository → ReactFlow 展示。`src/contracts/canvas.ts` 不包含 ReactFlow 类型；`flowTypes.ts` 是展示层适配。`canvasPositions.ts` 只解析并保存同 ID 卡片的 x/y，清除站点数据后恢复发布布局。
4. `src/content/journal/*.md` → 生成专用 HTML/锚点 → 固定分页 → 不可变版本包。`current.json` 唯一激活，客户端只携带元信息、页映射与点击区域。普通 `dev`/`build` 无 Chromium 校验已有包；开发失配报告状态，生产失配失败。生成失败不改变上一份激活包。
5. `public/os-desktop/` → Justin Kit 扫描器 → 文件图标与窗口。组件运行时按内容渲染、窗口位置、手势拆分；站点活动 API 使用 `src/data/stores/activity/` 和 `src/infrastructure/server/activityStream.ts`，通过 Kit 共享订阅源将公开快照交给画布卡片。

## 变更与验证

- 改简历、作品或文件顺序：编辑 `src/content/site/`，运行 `test:unit`、`build` 和相关浏览器流程。
- 改画布发布内容：使用 `justinspace-canvas-content`，保持卡片 ID 和边端点有效，并验证本地位置恢复/重置。
- 改模型：保持 `ScenePort`；对照相同相机、视口和光照的重构前后画面，并检查 WebGL 失败入口及 GPU 释放。
- 改过场：只改 `src/animation/` 或场景实现，检查中断时的 URL、返回、监听器和资源状态。
- 改日记：先 `journal:build` 生成书页，再用 `journal:verify` 和 `build` 验证源、当前版本及 dist 一致；异常路径用隔离目录测试。

`check:boundaries` 使用 TypeScript 与 Astro AST，检查逆向导入、运行时循环、纯层平台访问，以及浏览器入口到 Node/服务端模块的传递链；`test:boundaries` 包含必须失败的违规夹具。`test:unit`、`check:types`、`build`、`build:release` 与 `test:e2e` 分别验证规则、类型、已有包构建、分页发布和真实浏览器行为。Docker 构建需要可用的 daemon，无法运行时单独报告。

## 状态和资源所有权

工作室实例 Store 持有灯、时钟、抽屉和稳定视角目标。scene 接受幂等设置并持有实际 Mesh/插值。日记 application 控制器负责文章、书签和进入退出；交互层解释 pointerId 与手势；动画层只采样活动时间；场景负责纹理工作集和有效绘制报告。取消返回独立结果，不能触发完成后的导航或书签写入。

海岛环境由 scene 内独立组持有，不进入家具拾取树。程序化沙岛承接原有家具坐标与阴影；水色与沙岛共享岸线参数。海面使用拉格朗日形式的多组 Gerstner 波：从静止质点坐标同时计算水平、垂直位移与切向导数，近岸衰减同时作用于位移和法线；总陡峭度限制在翻折阈值以下。算法参考 [NVIDIA GPU Gems 第一章](https://developer.nvidia.com/gpugems/gpugems/part-i-natural-effects/chapter-1-effective-water-simulation-physical-models)。细浪使用本地打包的 Three.js 示例法线贴图，反光来自程序化天空，不创建额外反射渲染通道。外观参数位于 `src/config/islandAppearance.ts`，取景计算归动画层。海水与现有动效共用一次 RAF 调度，仅在首页和可见过场推进时间；全屏内容、日记稳定阅读、后台时暂停。减少动态效果及轻量恢复模式保留静态海面。环境网格、材质和纹理加入 scene 的统一资源释放集合。

地形高度与确定性岩群布局由 `src/config/islandTerrain.ts` 共用：中央保持家具承载平面，后方与两侧形成局部隆起。岩石合并成单个网格，共享带湿润带与细节凹凸的材质；同一布局驱动浅水中的岩影和岩脚碎浪。相机取景包含岩石外沿与高度，环境阴影覆盖整座岛；岩石仍不参与家具拾取。

岛上植被采用确定性程序化网格：棕榈树具有弯曲树干、独立弧形叶轴和折叠小叶，岩边搭配蕨类、阔叶与草簇。树干和叶轴合并，叶片按植物划分网格以支持裁剪和细节选择；所有植物共享材质，不使用透明树冠平面。叶片细节层共享原始位置、法线、颜色、UV 和风锚点，保留每片叶子的外沿采样，只简化内部索引。选择依据主视图的物理像素误差与太阳阴影纹素预算，并带切换滞回；近距离使用完整几何，变形与阴影使用同一细节层。布局与树冠包围范围归外观配置，默认取景包含树冠。植被归环境组管理，不参与家具点击拾取；粗树干稳定，叶轴与叶片使用固定根部的分层微风形变。

天空与海面共用晴空辐射函数和天体方向，白天采用蓝天与窄地平线薄雾，傍晚随太阳高度变暖。`studioTime` 使用 SunCalc，按真实时间和观测经纬度计算太阳、月亮各自方位；默认观测点为上海，已保存的地区或有效定位由 `readObservation` 读取。北为 -Z、东为 +X。场景定向光随太阳或夜间可见月亮的位置更新阴影；天空使用随相机旋转、无平移的背景球体，绘制太阳和带月相的月亮。参数与材质职责见[工作室环境](../features/studio-environment.md)。默认视角统一由 contracts 提供，刷新恢复默认角度，重置取最近的等价首页角度。

站点资料统一在 `src/content/site/site.json`，repository 验证后由纯 selector 派生页面标题。`src/app/siteContent.ts` 将完整阅读记录和精简的模型标签分别组装，Three.js 不读取站点记录。

### 海岛工作区

`islandLeisure` 管理前侧石圈篝火、折叠椅、面向办公桌的电视与懒人沙发，以及靠近右岸的木码头。岸线的连续局部扩展由沙地、水色和取景共用；木板、立桩和椅架按材质合并，装饰不进入拾取树。篝火与游戏角使用无投影局部光，火焰复用微风时间，遵守暂停和减少动态效果规则。水平相机角度连续累积，支持多圈旋转；重置取最近的等价首页角度，设备进入先沿外围转到屏幕正面再靠近。

游戏角朝办公桌斜放，电视保持黑屏且不发出屏幕光。`leisureGeometry` 生成带下陷座窝的软包外壳和受拉下垂的折叠椅帆布；缝线跟随曲面。篝火椅使用相对火堆的布局偏移，移动火堆时一起平移；码头、边桌营灯负责夜间局部照明。

懒人沙发采用灰褐布料、饱满底座、厚前沿与受压塌陷的靠背，形体由连续填充面塑形。低层植被混合不等高蕨叶和细草，叶片包含弧面、渐尖轮廓及细微叶脉；网格按材质合并，并使用固定根部的风变形。

`dockBoat` 构建白色敞口划艇、内壳、肋骨、座板、桨和系泊绳，保持在装饰组内。艇身姿态采样共享波列与海面时间，系泊绳端点随艇移动；水材质使用船体逆变换排除干燥船舱内的水面。岸地采用贯穿海平面的连续坡度，浅水根据估算水深调整底色和礁石轮廓；浪沫由近岸水位、破碎泡纹和露出水面岩脚共同生成。完全浸没的礁石只参与水下轮廓，不产生环绕白沫。相关动效均随海面暂停，不另启渲染循环。

`islandDressing` 配置集中维护后方阔叶植物、低蕨、补充岩石与两侧生活物件的确定性布局。新增植物与岩石复用现有合并网格；旅行箱、背包、杂物木箱、布篮、木柜、边桌与桌面文具的非透明表面按材质合并，放在家具拾取树之外。两侧物件向工作区聚集，低箱、叠书、搭布与植物形成高低错落；桌椅下方的编织垫贴合地形，不抬高家具。地形采样确定落地高度，布景脚印检查拉绳、抽屉完整行程、椅子和前方通道间隙。两盏落地摆放的煤油灯与一盏棚后吊灯包含油壶、玻璃罩、灯芯和提手，灯芯及局部暖色点光源随昼夜变化；点光源不投影，玻璃独立排序，均无新增交互入口。`dressingMaterials` 提供木材、皮革、金属、陶器和纸张的程序化表面，以及随昼夜减弱的静态天空反光，不增加实时环境捕捉。文件内容与入口仍归地面的文件木箱所有。

工作区以 `workspaceAppearance` 共享桌面高度、抽屉原点与遮阳棚范围。电脑和 iPad 的屏幕锚点由设备模型提供，供进入与返回过场使用；`studioFiles` 单独构建桌旁地面文件木箱，并接入文件集合。木桌、木柜、摇椅木框、时钟和棚柱复用场景内木材纹理；摇椅使用有厚度的布面与缝边，棚布使用独立材质控制可见度。

点击摇椅后，整把椅子沿圆弧摇脚前后滚动并阻尼停稳，旋转与平移共同维持地面接触；重复点击在当前角速度上追加有界推动，减少动态效果时保持原位。遮阳棚位于家具拾取树外，拉绳朝侧后方落地。远景显示棚布，镜头接近桌面时按距离平滑淡出，包括近距离平视；电脑、iPad 及日记镜头过场期间保持淡出目标，结束后按距离恢复。布面用透明度混合渐隐，阴影保留同步的覆盖率变化，减少动态效果时直接应用目标透明度。

首页普通拖动和单指拖动用于环绕，双指触控支持捏合缩放与旋转，不提供拖动平移或 Shift 专用手势。拖动超过阈值后不触发物件点击。放大时仅将岛内物体作为新的观察目标，海面及外围不改变放大目标；缩放目标受共享岛岸轮廓约束。观察偏移随现有相机阻尼更新，保存在内存视图快照中，重置视角时清除，不写入持久化存储。

相机以带速度状态的临界阻尼跟踪目标；环绕响应系数为 44，缩放为 56。输入在同一 RAF 的时间基准下消费，第一帧即可推进相机，反向时保持连续速度。家具静态合批限制在同一父级内，保留材质、阴影、图层和渲染顺序边界，跳过命名对象、外部引用对象、透明材质和自定义局部坐标着色器。休闲区合批保留各物件的投影及接收阴影属性，绒毛不参与投影。

滚轮输入按绘制帧合并同方向增量，保留反向输入次序及缩放边界。缩放拾取为高密度静态网格预建分段包围盒，先排除射线未经过的面段，再用 Three.js 原始三角面检测确定命中；分段共享原始顶点与索引，不修改渲染网格或材质。动态几何、特殊拾取及已变更的几何回退到原始检测，场景退出时释放拾取索引引用。

`breeze` 提供空间传播的统一微风近似：棚布四角固定、自由边缘和腹部起伏，缝边同步变形；棕榈叶、蕨类与阔叶根据距固定端的距离弯曲，叶尖具有传播延迟和细微高频响应。垂布只扰动未受支撑部分，咖啡蒸汽与火焰受同向偏移。刚性家具、粗树干、积沙和岩石保持稳定。该效果是受约束的程序化近似，不是完整流体或布料求解器。风时间复用场景渲染循环，后台、全屏页面与完整日记期间暂停，减少动态效果和轻量模式冻结。棚布颜色、缝边、加固片与深度通道共用顶点形变，随实际绘制帧更新；风致阴影同步刷新，单纯棚布淡出只失效太阳阴影，关闭的台灯跳过阴影重绘。所有资源纳入统一释放。

`spring` 为摇椅与船只提供带速度状态的阻尼响应。小船从船首、船尾、左右舷和中心采样共享水面；升沉、俯仰和侧倾分别缓冲，船舱排水遮罩始终跟随实际船体逆矩阵。船绳复用顶点、法线和采样表，随端点距离改变下垂。固定船内构件按材质合批，装配完成后释放未被活跃网格使用的临时几何。

海面静态岸线权重、梯度和近岸涌水范围预计算到顶点属性；远海严格零贡献区域跳过泡沫计算。设备过场的位置曲线在对准与靠近阶段衔接速度，由同一进度驱动实时页面投影；投影尺寸由 ResizeObserver 缓存，屏幕坐标来自设备模型。
